# 9090 端口冲突与后端重启速查

> 适用项目：Erwang Blog
>
> 适用场景：后端更新后，`erwang` 服务启动异常、`9090` 被旧进程占用、接口返回旧结果、登录接口表现异常。

---

## 1. 什么时候用这份文档

如果你出现下面任何一种情况，就直接按这份文档执行：

- `systemctl restart erwang` 后服务起不来
- `journalctl -u erwang` 里出现 `Port 9090 was already in use`
- 明明上传了新 jar，但接口返回还是旧逻辑
- `curl /api/auth/login` 还在报旧错误
- 页面表现和新代码不一致

---

## 2. 最短处理流程（推荐直接照抄）

### 第一步：停止服务

```bash
systemctl stop erwang
```

### 第二步：强制清掉可能残留的旧 Java 进程

```bash
pkill -9 -f "/www/server/erwang/backend/app.jar"
pkill -9 -f "/www/wwwroot/blog-backend-1.0.0.jar"
```

### 第三步：检查 9090 是否还被占用

```bash
lsof -nP -iTCP:9090 -sTCP:LISTEN
```

#### 情况 A：没有输出
说明 9090 已经释放，可以继续启动服务。

#### 情况 B：还有输出
例如：

```bash
java    825455 root   19u  IPv6  ...  TCP *:9090 (LISTEN)
```

那就直接按 PID 杀掉：

```bash
kill -9 825455
sleep 2
lsof -nP -iTCP:9090 -sTCP:LISTEN
```

如果还有新的 PID，就继续 `kill -9 新PID`，直到 **9090 没有任何输出**。

### 第四步：重新启动正式服务

```bash
systemctl start erwang
systemctl status erwang --no-pager
```

### 第五步：确认 9090 现在是 `erwang` 服务占用的

```bash
lsof -nP -iTCP:9090 -sTCP:LISTEN
systemctl show erwang -p MainPID -p ExecMainPID -p SubState
```

目标：

- `lsof` 看到的 PID
- 和 `systemctl show erwang` 里的 `MainPID`

应该是同一个。

---

## 3. 重启后必须验证的两个接口

### 验证文章接口

```bash
curl --max-time 10 http://127.0.0.1:9090/api/articles
```

### 验证登录接口

```bash
curl --max-time 10 -X POST http://127.0.0.1:9090/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'
```

如果这两条都正常，再去浏览器验证页面。

---

## 4. 一条命令版（紧急处理）

如果你已经很明确就是 9090 被旧进程占了，可以直接按这一组执行：

```bash
systemctl stop erwang && \
pkill -9 -f "/www/server/erwang/backend/app.jar" ; \
pkill -9 -f "/www/wwwroot/blog-backend-1.0.0.jar" ; \
sleep 2 ; \
lsof -nP -iTCP:9090 -sTCP:LISTEN ; \
systemctl start erwang ; \
systemctl status erwang --no-pager
```

> 注意：如果 `lsof` 仍然有输出，就按文档第 2 节里的 PID 方式继续手动杀。

---

## 5. 为什么会反复发生

这个问题通常是因为你之前混用了多种启动方式：

- `nohup java -jar ...`
- `systemctl start erwang`

只要旧的 `nohup` 进程没清掉，新服务就会抢不到 9090。

所以后续建议：

### 正式环境只保留一种启动方式

只用：

```bash
systemctl restart erwang
```

不要再用：

```bash
nohup java -jar app.jar ...
```

除非你是在临时排障。

---

## 6. 发布后的标准动作

每次你上传新 jar 后，建议固定执行：

```bash
systemctl restart erwang
systemctl status erwang --no-pager
curl --max-time 10 http://127.0.0.1:9090/api/articles
```

如果结果不对，再走本篇文档的“9090 清理流程”。

---

## 7. 常用命令汇总

### 看 9090 被谁占用

```bash
lsof -nP -iTCP:9090 -sTCP:LISTEN
```

### 看某个 PID 是谁

```bash
ps -fp PID
```

### 杀掉指定 PID

```bash
kill -9 PID
```

### 看服务主进程

```bash
systemctl show erwang -p MainPID -p ExecMainPID -p SubState
```

### 看服务日志

```bash
journalctl -u erwang -n 120 --no-pager
```

---

## 8. 判断这次是不是已经切到新后端

如果你怀疑“磁盘上的 jar 换了，但运行的还是旧进程”，用这个判断：

1. `lsof -i :9090` 拿到监听 PID
2. `systemctl show erwang -p MainPID`
3. 两个 PID 必须一致

如果不一致，就说明你打到的不是 `erwang` 这个新服务。
